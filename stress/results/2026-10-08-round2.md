### New in round 2

- **Z11. zig's MinGW runtime lacks `__guard_dispatch_icall_dummy`**
  (Windows; toolchain; a regression for magick). magick's link stops:
  `lld-link: error: undefined symbol: __guard_dispatch_icall_dummy >>>
  referenced by libmingw32.lib(mingw_cfguard_support.obj)`.
  mingw-w64 defines `__guard_dispatch_icall_fptr` in
  `cfguard/mingw_cfguard_support.c` and its target in
  `cfguard/guard_dispatch.S`. zig 0.16.0 ships the `.c` file only:
  `lib/libc/mingw/cfguard/` holds `mingw_cfguard_support.c` alone in
  conda-forge's zig and in upstream's (checked by the reporter). What pulls
  it in is code built with Control Flow Guard. The clang-x86_64 r-windows
  ImageMagick bundle's `librsvg-2.a` holds Rust's std; its `std`, `core`,
  `alloc`, `panic_unwind`, `memchr` and `object` objects reference
  `__guard_dispatch_icall_fptr` (nm, by the reporter). Why it shows
  now: S10 puts the env's `-L` after the package's. In round 1 (its
  `--trace` log) the env's `-L` came first, so `-lrsvg-2`, `-lcairo` and
  the rest bound the conda env's import libraries; now the bundle's static
  libraries bind, as on CRAN. Repro, by the reporter with both zigs:
  `zig cc -target x86_64-windows-gnu -shared -mguard=cf lib.c` fails the
  same way. It links once an object defining
  `__guard_dispatch_icall_dummy: jmp *%rax` is added. Experiment on
  kappa: `PKG_LIBS += guard_dispatch.o` makes magick install, load, pass
  its smoke call and unload (61.9 MB; round 1's DLL-linked build was 11.6
  MB). Candidate fix: `round2/kappa/diffs/rzig-z11-cfguard.diff` (against
  fix-stress-round1; `git apply --check` passes). A new `cfguard.zig`
  embeds guard_dispatch.S's two lines. rzig assembles it once into its
  cache (`cfguard-<key>/guard_dispatch.o`), through a new
  `cache.compiled()` that `dso_fini.zig` now uses too. `compiler.zig`
  passes it on every Windows link: a command with `-o` and no
  compile-only flag, so `--version`, windres's `-E` and `-c` get
  nothing. parity-test.sh filters it like S9's object. The kappa runner
  checked it on gamma: unit tests 71 of 71, parity 0 failed, and a
  Windows cross-build. It was not run end to end through a patched
  `rzig.exe`. The core:

  ```
  /* mingw-w64-crt's cfguard/guard_dispatch.S, x86_64 */
      .text
      .globl __guard_dispatch_icall_dummy
  __guard_dispatch_icall_dummy:
      jmp *%rax
  ```

  ```diff
  +    const cfg = if (ctx.os == .windows and cfguard.wanted(args)) try cfguard.object(ctx) else null;
  ...
       if (fini) |o| try out.append(a, o);
  +    if (cfg) |o| try out.append(a, o);
  ```

  As a plain object, the stub is linked into every Windows DLL and
  program; only code built with CFG ever jumps to it. An untested variant
  puts it in an archive, which lld-link would pull only when
  `mingw_cfguard_support.obj` needs it.
- **Z12. zig's MinGW headers lack the WinRT headers** (Windows; toolchain;
  found only in an experiment). With conda's abseil hidden from
  pkg-config (`PKG_CONFIG_PATH` and `PKG_CONFIG_LIBDIR` naming only the
  openssl `.pc` files), s2's `configure.win` builds its bundled abseil.
  CMake, make, `g++.exe` and `bin/Rscript` all work (S14, S15).
  Then: `absl/time/internal/cctz/src/time_zone_lookup.cc:51:10: fatal
  error: 'windows.globalization.h' file not found`. abseil includes it
  when `NTDDI_VERSION >= NTDDI_WIN10_NI` (its comment: MinGW added the
  header at that SDK version). zig's `_mingw.h` defaults `_WIN32_WINNT`
  to 0xa00, so `sdkddkver.h` sets `NTDDI_VERSION` to
  `WDK_NTDDI_VERSION`, Windows 11. But zig's `any-windows-any` has none
  of mingw-w64's `windows.*.h` WinRT headers (`windows.globalization.h`,
  `windows.foundation.h`), only `roapi.h`, `inspectable.h` and
  `hstring.h`. Repro, by the reporter with both zigs: a three-line file
  with abseil's guard fails, and compiles with
  `-DNTDDI_VERSION=0x0A00000B`. Not tried on kappa. Who reaches it:
  `configure.win` builds the bundled abseil whenever `pkg-config
  absl_base` fails, which happens to a Windows user without a libraries
  env. sf and lwgeom need s2.
- **SD2. terra on Windows wants TBB headers** (sysdep, from S18).
  terra's `Makevars.ucrt` pkg-config branch adds `-DHAVE_TBB` and
  `-ltbb12` (Rtools has oneTBB). The win-64 stress env has no tbb-devel

- **P6. rstan's model compile on Windows** (package; the smoke call, new
  in decision 21). rstan 2.32.7's `R/plugin.R` adds `-std=c++1y` on
  Windows. On the model's compile line it comes after `-std=gnu++17`, and
  StanHeaders 2.39.1 needs C++17: `no member named 'is_same_v' in
  namespace 'std'`. With `CXX17FLAGS += -std=gnu++17` (experiment) the
  model compiles and samples, then the unload and R's exit return 0.
  Round 1 never got this far on Windows. fix-stress-round1's kappa tester

- **H2. CMake on macOS searches Homebrew whatever PATH says** (harness;
  an isolation gap, not a failure). arrow's default row links
  `/opt/homebrew/lib/libsnappy.a` (twice in its `PKG_LIBS`).
  CMake 4.4's `Modules/Platform/Darwin.cmake` runs `brew --prefix`. When
  that fails, as under the narrowed PATH, it prepends `/opt/homebrew` on
  arm64 (`/usr/local` on Intel) to `CMAKE_SYSTEM_PREFIX_PATH` (checked
  in the stress env's cmake 4.4.4, lines 242-261). PATH does not help:
  `find_library` searches PATH's own directories (`<env>/bin`); mapping
  them to `<prefix>/lib` was Windows-only and was removed in 3.28
  (`Help/command/find_library.rst`). So the env's `lib` is reached only
  through `CMAKE_SYSTEM_PREFIX_PATH`, where the probe printed
  `/opt/homebrew;/usr/local;/usr;/` before the env. Experiment 1: a
  CMake probe under `PATH=<env>/bin:/usr/bin:/bin` finds
  `/opt/homebrew/lib/libsnappy.dylib`. With a toolchain file setting
  `CMAKE_SYSTEM_IGNORE_PREFIX_PATH` it finds the env's. Experiment 2:
  arrow alone with the patched runner: ok in 9.02 min, smoke and unload
  ok, and `PKG_LIBS` names no `/opt/homebrew`. libarrow then builds its
  own snappy. So the README's "Homebrew ... cannot step in" is wrong for
  CMake builds. The other CMake rows' logs name no Homebrew library.
  Candidate fix (`round2/omicron/diffs/stress-cmake-homebrew.diff`;
  `git apply --check` passes on this branch). It also changes the README
  and `--help`. Its stress.R part:

  ```diff
  +if (os == "macos" && !flag("keep-path") && nzchar(sysroot)) {
  +  tc <- file.path(out, "no-homebrew.cmake")
  +  writeLines("set(CMAKE_SYSTEM_IGNORE_PREFIX_PATH /opt/homebrew /usr/local)", tc)
  +  Sys.setenv(CMAKE_TOOLCHAIN_FILE = tc)
  +}
  ```
